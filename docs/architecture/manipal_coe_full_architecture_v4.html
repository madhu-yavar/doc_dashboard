🔄 Agent Architecture Flow

Orchestrator → Agents → Skills → Tools → LLM

Current runtime: the Express server supports two intake paths. PDFs go through DocumentTypeRouter, which classifies the document and routes it to a specialized extractor agent. Voice dictations go through a swappable STT boundary, then VoiceExtractorAgent, shared dashboard mapping, and dashboard-readiness validation before a record can remain processed. In the current workspace, Gemini STT is the active path; the voice architecture is intentionally modular so Whisper can become the primary STT backend with Gemini as fallback. ReActExtractionAgent exists in the repository but is optional rather than the default document-processing path. Processing Insights are served separately from analytics.sqlite through /api/analytics/overview.

Storage Discipline

All writes pass through the same storage boundary. PDF queue rows, voice sessions, transcripts, extraction output, chat state, note drafts, citations, and audit events are persisted as stored system state.

Read Discipline

The UI does not bypass storage. Queue rows, dashboards, chat context, and timelines are all hydrated from stored read models rather than ad hoc client state.

Inference Guardrail

Primary extraction runs on self-hosted Gemma. The current voice STT path uses Gemini, and every response or extraction path is expected to meet grounding, readiness, and policy checks before display.

Operational Envelope

Router <1s • Chat 3-8s • SOAP 15-25s • PDF extraction 30-45s • Voice varies by audio length
