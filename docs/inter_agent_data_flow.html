Code-grounded runtime architecture for the Doctor Dashboard agent system. This document is based on the implemented server entrypoints and live agent classes under doctor_dashboard/agents, not the incomplete registry layer.

The diagrams deliberately separate three things: live entrypoints, implemented agents, and the skills/tools/storage services each agent touches.

System Overview

Three live runtime orchestration paths exist today: extraction and dashboard mapping, doctor-assistant chat orchestration, and chart-note generation/export. The dashboard presentation agent is active through a skill, not through a server-level direct instantiation.

Runtime Notes

  • DashboardPresentationAgent is live, but only through DashboardMapperSkill.
  • CrossValidationAgentSkill is on the chart-note path even though it is a skill, not an agent.
  • PDF export prefers cached chart notes; if none exist, the export endpoint currently uses a direct GemmaClientTool + PromptBuilderTool fallback instead of ChartNoteAgent.
  • Registry files describe additional agents/tools/skills, but missing handlers mean they are not part of the live runtime flow.

Agent + Data Handoff View

This view focuses on live call order, main payloads, and where data is persisted or exits the agent system.

Extraction Pipeline

Upload Center / API

Uploads PDFs, starts per-document SSE processing, and consumes processed dashboard responses

file buffer -> uploaded file path -> { documentId, name, filePath }

DischargeExtractorAgent

Consumes pdfPath and emits stepwise extracted data, validation, and usage

agentResult = { data, validation, steps, tokensUsed }

DashboardMapperSkill

Transforms extraction output into dashboard cards, sample patient data, and presentation input

presentationInput = { vitals, diagnosis, meds, labs, radiology, treatment, notes, provenance }

DashboardPresentationAgent

Generates summary_cards and notes_rail

document.result = { dashboard_cards, sample_patient_data, presentation, extracted_data }

Document Storage + API Response

Writes processed document back to storage and emits live progress / final document payload

load(documentId, chatId) before orchestration and save(session) after answer generation

QueryIntentAgent

Outputs classification + sectionHints

conditional branch

Clarification / Consent Return

If needsClarification or external consent is required, the agent returns early with a low-confidence assistant message and updated session state.

mainline only when classification can proceed

RecordContextAgent

Inputs: document + message + sectionHints + classification

internalEvidence + sections

ExternalKnowledgeAgent

Inputs: query + classification only when needsExternal is true

externalEvidence + source/error metadata

SafetyGuardAgent

Scores confidence and decides refusal policy from internal + external evidence

confidence + refusal + answer route

AnswerComposerAgent

Builds final answer payload and citations unless safety refuses or external search has no result

ActionRouterAgent

assistant message + citations + confidence + proposed_actions

Session + Action + Export Storage

Session is saved immediately. Confirm and export endpoints persist actions and exports into dedicated collections.

Chart Note Pipeline

Chart Note Endpoints

GET/POST /api/documents/:id/chart-note

document.result.extracted_data + document.filePath

CrossValidationAgentSkill

Produces validated citations, confidence summary, and fields needing review from extracted data and PDF text

validationSummary + citationData

ChartNoteAgent

Consumes { extractedData, pdfText, citationData, validationSummary } and returns SOAP note content plus reasoning steps

chart note payload

Document.chartNote Cache

Generated note, reasoning steps, validation, and citations are persisted onto the document record

PDF export branch

POST /api/documents/:id/chart-note/pdf

Uses cached chart note when present. If not cached, it runs a direct tool path: PdfReaderTool -> CrossValidationAgentSkill -> PromptBuilderTool -> GemmaClientTool before rendering PDF.

Per-Agent Drilldown

Compact cards for each implemented agent: purpose, caller, inputs, outputs, downstream dependencies, and important guards or failure behavior.

DischargeExtractorAgent

Called By
Processing endpoints in server/index.cjs
Purpose
Read PDF and execute the sequential extraction + validation skill pipeline.
Inputs
pdfPath, optional pdfName, optional onProgress
Outputs
{ data, validation, steps, detailedSteps, tokensUsed }
Downstream
PDFReaderTool, GemmaClientTool, PromptBuilderTool, ProvenanceBuilderTool, 7 extraction skills
Guards
Fails hard on unreadable PDF; otherwise continues past failed steps when requireAllSteps is false.

DashboardPresentationAgent

Called By
DashboardMapperSkill
Purpose
Convert dashboard data into UI-facing summary cards and notes rail content.
Inputs
{ dashboardData }
Outputs
{ summary_cards, notes_rail }
Downstream
SummaryCardBuilderSkill, NotesRailBuilderSkill, and 4 presentation tools
Guards
Returns failure when no dashboard data is provided.

DoctorAssistantAgent

Called By
POST /api/chat/query
Purpose
Load chat state, classify intent, collect evidence, enforce safety, compose answer, route actions, and persist the session.
Inputs
{ document, documentId, message, sectionContext, chatId }
Outputs
{ answer, citations, confidence, proposed_actions, session }
Downstream
QueryIntentAgent, RecordContextAgent, ExternalKnowledgeAgent, SafetyGuardAgent, AnswerComposerAgent, ActionRouterAgent, SessionMemoryAgent
Guards
Can return early for clarification or external-search consent before evidence retrieval begins.

QueryIntentAgent

Called By
DoctorAssistantAgent
Purpose
Classify query intent and resolve section hints for downstream evidence retrieval.
Inputs
{ message, sectionContext }
Outputs
classification + sectionHints
Downstream
QueryClassifierTool, SectionHintResolverTool
Guards
No explicit refusal logic; always returns a classification object for the parent agent to interpret.

RecordContextAgent

Called By
DoctorAssistantAgent
Purpose
Search the processed document for safe internal evidence and section snapshots.
Inputs
{ document, message, sectionHints, classification }
Outputs
{ evidence, sections, source_class }
Downstream
RecordContextSearchTool, SectionContextFetchTool, ProvenanceGateTool
Guards
Filters internal results through provenance gating before returning them.

ExternalKnowledgeAgent

Called By
DoctorAssistantAgent when classification.needsExternal is true
Purpose
Search approved medical web sources, filter/rank them, and normalize citations.
Inputs
{ query, classification }
Outputs
{ evidence, source_class, error, error_type }
Downstream
MedicalWebSearchTool, SourcePolicyTool, ExternalSourceRankerTool, ExternalCitationNormalizerTool
Guards
Returns a structured empty-success payload even when external search fails.

SafetyGuardAgent

Called By
DoctorAssistantAgent
Purpose
Compute confidence and decide whether the agent should refuse the answer.
Inputs
{ classification, internalEvidence, externalEvidence }
Outputs
{ confidence, refusal }
Downstream
ConfidenceScorerTool, RefusalPolicyTool
Guards
Acts as the final safety gate before answer composition.

AnswerComposerAgent

Called By
DoctorAssistantAgent
Purpose
Compose the final clinician-facing answer and assemble citations.
Inputs
{ message, classification, internalEvidence, externalEvidence, chatHistory }
Outputs
{ answer, citations, source_class }
Downstream
GemmaClientTool, ChatPromptBuilderTool, CitationAssemblerTool
Guards
Uses a direct fact-answer shortcut for supported factoid questions with internal evidence only.

ActionRouterAgent

Called By
DoctorAssistantAgent
Purpose
Convert action-style requests into explicit proposal payloads for note updates, abnormal flags, or chat export.
Inputs
{ classification, message, evidence, documentId }
Outputs
{ proposals }
Downstream
NoteUpdateSuggesterSkill, AbnormalFlagActionSkill
Guards
Returns no proposals when classification.isActionRequest is false.

SessionMemoryAgent

Called By
DoctorAssistantAgent
Purpose
Load an existing chat session or save an updated session object.
Inputs
load(documentId, chatId) and save(session)
Outputs
Session record or null; persisted session after save
Downstream
Configured collection readers/writers bound by the server
Guards
No business logic beyond lookup and upsert by chatId.

ChartNoteAgent

Called By
Chart note GET/POST endpoints
Purpose
Generate a SOAP-style chart note through a seven-step reasoning and writing loop.
Inputs
{ extractedData, pdfText, citationData, validationSummary }
Outputs
{ chart_note, reasoning_steps, metadata }
Downstream
GemmaClientTool, PromptBuilderTool
Guards
Returns a structured failure payload on generation errors; chart-note PDF export does not always go through this agent.
